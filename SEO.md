## 8. STRUKTUR NAVIGASI DAN PELUANG GOOGLE SITELINKS

Saya ingin ketika seseorang mencari **“Jasa Angkut Slamet”**, hasil pencarian Google berpotensi menampilkan website utama beserta beberapa tautan halaman tambahan di bawahnya, seperti yang kadang terlihat pada pencarian merek besar seperti Facebook.

Istilah fitur tersebut adalah **Google Sitelinks**.

**Perlu dipahami: Google memilih sitelinks secara otomatis. Tidak ada meta tag, schema, atau kode khusus yang dapat memaksa Google menampilkan sitelinks tertentu.** Tugas kita adalah membuat struktur website mudah dipahami dan halaman penting mudah ditemukan.

Implementasikan hal berikut:

1. Pertahankan seluruh menu navigasi asli.
2. Pastikan setiap menu memiliki link HTML yang dapat dirayapi (`<a href="...">`) dan bukan hanya elemen klik JavaScript tanpa URL.
3. Gunakan teks anchor yang deskriptif, singkat, dan sesuai tujuan.
4. Pastikan halaman penting dapat dicapai dari homepage melalui navigasi atau internal link.
5. Gunakan judul halaman dan heading yang informatif serta tidak berulang.
6. Jika navigasi saat ini menggunakan anchor section satu halaman, pertahankan perilakunya. Jangan mengubahnya menjadi halaman terpisah tanpa alasan.
7. Jika terdapat halaman terpisah, gunakan URL yang stabil dan deskriptif.
8. Buat breadcrumb yang terlihat jika sesuai dengan struktur halaman.
9. Jangan membuat halaman duplikat hanya untuk memperbanyak sitelinks.
10. Jangan membuat link tersembunyi khusus crawler.
11. Jangan memakai `meta keywords`, `meta name="google-site-verification"` palsu, atau schema buatan untuk mencoba memaksa sitelinks.
12. Jangan membuat halaman login palsu. Referensi Facebook hanya untuk contoh tampilan hasil pencarian dengan tautan tambahan, bukan untuk meniru layanan login Facebook.

Setelah audit, buat tabel laporan:

- URL/anchor
- Status dapat dirayapi
- Title halaman/section
- Rekomendasi perbaikan

## 11. TECHNICAL SEO

Audit dan implementasikan:

### Crawling dan indexing
- `robots.txt` tersedia dan tidak memblokir halaman penting.
- XML sitemap tersedia di `/sitemap.xml`.
- Sitemap hanya berisi URL canonical yang boleh diindeks dan berstatus 200.
- Tambahkan sitemap ke robots.txt.
- Gunakan URL absolut HTTPS.
- Periksa redirect HTTP ke HTTPS dan versi domain yang konsisten.
- Pastikan tidak ada halaman penting yang tidak sengaja `noindex`.
- Pastikan tidak ada canonical yang salah.
- Periksa status HTTP halaman, 404, redirect chain, dan broken link.
- Pastikan halaman penting dapat ditemukan melalui link internal.

### Rendering
- Periksa HTML hasil server dan hasil render browser.
- Pastikan title, meta description, canonical, heading, teks utama, link navigasi, dan structured data dapat dibaca Google.
- Jika menggunakan React/Next.js/Vite atau framework lain, gunakan pendekatan rendering yang sesuai dengan framework yang benar-benar dipakai.
- Prioritaskan SSR/SSG/prerender jika diperlukan dan cocok dengan arsitektur proyek.
- Jangan melakukan migrasi framework tanpa alasan yang jelas.

### Performance dan Core Web Vitals
- Optimalkan LCP, INP, dan CLS.
- Optimalkan ukuran foto dengan format modern seperti WebP/AVIF jika aman.
- Gunakan lazy loading untuk gambar di bawah fold.
- Jangan lazy-load gambar utama/LCP secara sembarangan.
- Tetapkan width dan height/aspect ratio gambar untuk mencegah layout shift.
- Minimalkan JavaScript yang tidak diperlukan.
- Hindari font dan script yang memblokir render.
- Pastikan website nyaman digunakan di Android dan perangkat mobile.
- Jangan mengorbankan fungsi kalkulator tarif, peta, atau fitur utama demi skor Lighthouse.

### Aksesibilitas dan HTML
- Gunakan elemen semantic HTML.
- Setiap gambar informatif memiliki alt text yang menjelaskan isi gambar.
- Gambar dekoratif dapat menggunakan alt kosong.
- Tombol dan link memiliki nama yang jelas.
- Pastikan kontras dan fokus keyboard memadai.
- Gunakan bahasa dokumen `lang="id"`.
